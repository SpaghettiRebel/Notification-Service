# Notification-Service

Event-driven notification service – сервис принимает события через API, кладёт их в Kafka, воркеры читают события и отправляют уведомления через разные каналы: email-заглушка, Telegram-заглушка, SMS-заглушка.

## Надёжность

- API требует заголовок `Idempotency-Key` (8–128 символов) и возвращает стабильный `event_id` для повторного запроса.
- Воркеры фиксируют Kafka offset только после отправки либо подтверждённой записи события в DLQ.
- Обработка защищена lease-механизмом в PostgreSQL; зависшие `PENDING` восстанавливаются автоматически.
- Повторы отправки ограничены по числу и времени, невалидные сообщения попадают в `notification.invalid.dlq`.

Перед запуском обновите схему БД: `python -m alembic upgrade head`. Readiness API доступен на `/health`, liveness — на `/live`.
